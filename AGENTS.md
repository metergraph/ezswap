# Working in metergraph-replay

## Public repository rules

This repository will be public. Before publishing a branch, commit, issue,
pull request, comment, release, screenshot, fixture, or log:

- Write a self-contained public description. Keep private tracker IDs, links,
  discussion, and customer context out of branch names, commit messages,
  issue or PR text, code comments, and release notes.
- Remove secrets, tokens, non-public customer or prospect names and domains,
  tenant or workspace IDs, captured prompts or responses, private paths, and
  cloud account or resource IDs. Use synthetic examples and `example.com`.
- Fixtures and demo data are synthetic only.
- Run `python3 scripts/check_publication.py origin/main` before pushing.

## What this is

A local command-line tool: read LLM call traces from a file, replay each call
on other models through an OpenAI-compatible endpoint the user brings, and
report cost, latency and output statistics against production's recorded
output and against a noise floor (production's model replayed twice against
itself). No account, no telemetry; nothing leaves the machine except the
provider calls the user asked for.

Two commands sit beside `run`:

- `map` groups calls into parts (places in an app that call a model),
  replays a sample of each part, and prints the sensitivity map: which parts
  change beyond what a rerun of production's own model does.
  `estimate --map` lists the parts and writes the names file
  (`replay-parts.json`, beside the trace file). `docs/sensitivity-map.md` is
  the specification of every rule; keep it in step with the code.
- `record` is a local reverse proxy on 127.0.0.1 that forwards an app's
  model calls to one upstream and appends each captured call to
  `traces.jsonl`. It must never write or print a header (other than the two
  cleaned `X-Replay-*` values) or a query string. `docs/record.md` describes
  it.

## Layout

| Path | Owns |
|---|---|
| `cmd/metergraph-replay/` | The binary's entry point. |
| `internal/types/` | Shared contracts (`RunFile`, `Case`, ...). Every package builds against them. |
| `internal/core/` | Pure statistics over a run: per-arm summary, noise floor, tracked-field comparisons, sentences, spreads, bootstrap. No I/O. |
| `internal/jsnum/` | JavaScript number formatting and rounding, so figures match the hosted product digit for digit. |
| `internal/cases/` | Request parsing and replayability rules: `CapturedCall` to `Case`. |
| `internal/adapters/` | Trace file readers: replay JSONL, raw provider logs, Langfuse export, OTel GenAI. Each also reads the part name (`part`, or the `--part-key` key). |
| `internal/parts/` | Parts for the map: the fingerprint, part keys and default names, grouping, `--only` and `--name`, the compared fields of a part, and the names file. |
| `internal/record/` | The recording proxy behind `record`: forwarding, which requests are model calls, rebuilding streamed answers, and the trace file writer. |
| `internal/providers/` | OpenAI-compatible chat client: retries, fallbacks, usage normalization. |
| `internal/pricing/` | Price catalog (`prices.json`, generated by `cmd/build-prices`), cost function, and the Pricing API lookup for models the catalog lacks (`lookup.go`). |
| `internal/run/` | Estimate, budget, replay orchestration, writing `run.json`. `plan.go` also plans a map: it samples each part (`planParts`). |
| `internal/report/` | The printed report. `model.go` holds every figure and sentence, `render.go` draws it; primitives are in `term/`. The map is `map.go` (counts and labels), `paired.go` (the paired sign test) and `map_render.go`. |
| `internal/explore/` | The interactive explorer (Bubble Tea): pure state, reducer and screen, plus the program. |
| `internal/tui/` | The spend confirmation and run progress on an interactive terminal. |
| `internal/cli/` | Commands: `demo`, `estimate`, `run`, `map`, `record`, `report`. `map.go` holds the map commands and the table of which command takes which option; `record.go` the recorder's command. |
| `cmd/build-demo/` | Regenerates `demo/traces.jsonl` and `demo/run.json`, and the map demo: `demo/map-traces.jsonl` and `demo/map-run.json` (`map.go`). |
| `cmd/build-prices/` | Regenerates `internal/pricing/prices.json` from metergraph-core's `prices.yaml`. |
| `conformance/` | Fixtures that pin numbers shared with the hosted Metergraph product. Never edit expected values by hand. |
| `demo/` | Synthetic traces and recorded outputs for `demo` and `demo --map`, embedded in the binary. |
| `examples/` | Small sample apps. `support-desk` calls a model from three parts through the recorder, for trying `record` and `map` end to end. Synthetic content only. |
| `npm/`, `scripts/npm-packages.mjs` | The npm launcher package and the script that builds the per-platform packages from a GoReleaser build. |
| `.goreleaser.yaml` | Release builds, archives and the Homebrew cask. |

## Conventions

- Go (the version in `go.mod`). Format with `gofmt`; `go vet ./...` and
  `go test -race ./...` must pass, and `go mod tidy` must leave no diff.
- Few dependencies: the Charm libraries for the terminal UI and
  `go.yaml.in/yaml/v3` for `cmd/build-prices`. Ask before adding another.
- Tests sit beside the code (`*_test.go`), with fixtures in each package's
  `testdata/`. Report output is pinned by golden files in
  `internal/report/testdata/golden`; `go test ./internal/report -update`
  rewrites them. Review the diff before committing it.
- Some fixtures are frozen output of the earlier TypeScript implementation
  (`internal/report/testdata/model`). Do not regenerate them from the Go
  code: a difference means the report changed.
- User-facing copy: no em dashes. Use a full stop, comma, colon or brackets.
  A bare `—` as a missing-value marker in a table cell is fine.
- Statistics are presentation, not a verdict. Nothing says a model is good
  enough to switch to.
